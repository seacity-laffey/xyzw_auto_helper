## Adaptations and preserved behavior

- Keep dev navigation, shared UI components, batch lifecycle, task templates,
  desktop game sessions, synchronized input, and current club reports.
- Large upstream views are reimplemented as small presentation components,
  composables and pure data helpers. Generated Apex configuration is stored
  separately in `src/assets/data/apexSnapshot.json`.
- Apex batch execution visits all open rounds. Interrupted pagination remains
  retryable; incomplete vote boards do not replace the last complete board.
- New batch activities preserve pre-existing connections, release only acquired
  slots, stop before subsequent writes, and expose failures in account status.
- Camp targets are limited to the current match date. Defender counters are
  refreshed before each attack. Mirrors never inherit the real member's attacks.
- Camp defaults: at most three attacks per invocation (within the server daily
  limit), three pet rounds, then eligible rewards. Xuanwu includes one lottery
  draw, explicitly named in both manual and scheduler entries.
- Saved credentials always retain a local BIN for dev game startup. Credential
  regeneration uses the existing encoder, without requiring game runtime globals.
- SMS proxy support covers Vite, Cloudflare and the Electron endpoint allowlist.
- Backend car task definitions and protocol leftovers are removed. No existing
  database rows or scheduled jobs are migrated or deleted.
- New commands use dev's `CommandRegistry`; no duplicate command-builder layer.
